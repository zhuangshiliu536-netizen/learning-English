# 英语启蒙 App 从零规划与关键里程碑（详细整合版）

- 文档版本：v1.0（讨论整合版）
- 整理日期：2026-11-04
- 文档状态：整体方向与目标范围已明确，执行参数待逐项确定
- 适用范围：从零启动的英语启蒙 App 产品
- 规划原则：独立规划，不依据现有 Demo、代码完成度或既有排期估算
- 时间口径：所有周数、月份均从正式启动日计算；实际启动日期尚未确定

## 1. 总体规划与边界

建议按 **12 个月**规划：前 **28 周**完成产品建设、家庭验证和小范围收费上线，另留 **4 周机动时间**，首发窗口按约 **7—8 个月**管理；第 **9—12 个月**根据实际使用与经营证据，决定下一阶段投入。

每个阶段以交付物和验证证据验收。未通过时，可以返工、缩小范围、延长观察或暂停投入，再重新估算后续安排。时间到达本身不代表里程碑通过。

### 1.1 已确认项与规划假设

| 项目 | 规划口径 | 状态 |
| --- | --- | --- |
| 目标年龄 | 3—8 岁，按年龄与已有能力提供不同路径 | 用户已明确 |
| 团队方式 | 小团队，全员使用 AI 辅助工作 | 用户已明确 |
| 规划起点 | 从零启动，忽略现有 Demo 情况 | 用户已明确 |
| 投入规模 | 暂按约 4—6 人等效稳定投入估算，允许兼任角色 | 排期假设，实际人数与工时待定 |
| 首版学习目标 | 听懂熟悉生活场景中的英语，并作出合适回应 | 建议，待讨论 |
| 首发范围 | 一个主要市场、一个首发平台 | 建议，具体地区与平台待定 |
| 时间目标 | 约 7—8 个月小范围收费上线，第 9—12 个月作出经营决策 | 规划目标，需按首月实测产能校准 |
| 预算与收费方式 | 根据团队投入、内容成本、平台和服务成本确定 | 待确定 |
| 招募规模与验收阈值 | 按本稿建议起步，在正式测试前确定 | 工作量建议，不是已验证结论 |

“全员 AI”首先是团队的工作方式。App 内是否加入 AI 对话、语音评测等功能，按教学价值、体验和成本单独决定。

### 1.2 周期管理口径

- 28 周是主计划，4 周缓冲用于处理招募、返工、发布与其他不确定性。
- 缓冲不用于预排新增必做功能。
- 第 9—12 个月从项目启动日计算。
- 首发上线、出现真实付费、形成可持续经营依据是不同节点。
- 团队投入、市场、平台或首版能力发生明显变化时，需要重新估算周期。
- 本文是最新讨论形成的规划基线；历史草稿中的不同人数、年龄优先级、时间或编号，不作为本版执行口径。

## 2. 3—8 岁的分层策略

建议通过共用产品底座、分层学习路径覆盖整体年龄范围。课程可以共用主题、素材和教学结构，再调整任务形式、语言难度与引导方式。

| 年龄段 | 建议的初始体验 | 核心验证问题 |
| --- | --- | --- |
| 3—4 岁 | 亲子共同参与，以声音、图片、动作和简单选择回应 | 家长是否容易带着用，孩子是否理解活动 |
| 5—6 岁 | 语音与图片引导，逐步自主完成听懂、选择和回应 | 能否形成稳定使用，成人帮助是否逐步减少 |
| 7—8 岁 | 更强的自主操作，按能力提供更丰富的任务与进阶内容 | 难度是否合适，内容是否有持续吸引力 |

上述划分是初始体验设计假设，需要通过家庭观察修正。

年龄用于推荐，已有英语能力决定学习起点。7 岁零基础和 5 岁已有基础的孩子，可能需要不同于年龄推荐的路径。

建议先围绕 5—6 岁完成第一个完整样板，再适配两端年龄。这属于制作顺序建议，整体目标仍为 3—8 岁。三个年龄段从样板阶段就参与观察，首发以三段均通过验收为目标。

若某一段尚未通过验收，需要明确选择延后整体发布，或缩小首发适用范围，并同步调整宣传与权益；未经决定与验证的范围不能自动计入首发完成情况。

## 3. 里程碑总览

| 时间 | 里程碑 | 核心交付与决策 |
| --- | --- | --- |
| 第 1—2 周 | M1：立项 | 明确定位、学习目标、资源约束与负责人 |
| 第 3—5 周 | M2：方向确认 | 验证需求，确定首版范围与试用招募计划 |
| 第 6—9 周 | M3：样板验收 | 完整教学与体验样板通过，生产流程可重复 |
| 第 10—17 周 | M4：内测准备完成 | 核心产品可运行，具备至少 4 周内容和家庭试用条件 |
| 第 18—23 周 | M5：家庭持续使用验证 | 完成连续观察、分组分析、关键问题修正与复测 |
| 第 24—28 周 | M6：付费试运营 | 小范围收费上线，购买、交付与问题处理可运行 |
| 主计划之外预留 4 周 | 机动窗口 | 处理不确定性，按实际发生调整后续时间 |
| 第 9—12 个月 | M7：下一阶段经营决策 | 决定扩大投入、聚焦人群、调整方案或收缩范围 |

主要依赖关系：

定位与需求明确 → 完整样板通过 → 批量开发与内容生产 → 家庭持续使用验证 → 小范围真实收费 → 经营决策。

## 4. 各阶段详细安排

### 4.1 第 1—2 周：明确方向与投入边界，完成 M1

**阶段目标**

把产品、学习目标和资源约束说清楚，为后续研究与样板准备建立共同依据。

**主要工作**

- 明确目标家庭、孩子的英语基础、主要使用场景和家长参与程度。
- 选择首版优先解决的一个核心问题。
- 将学习目标写成可以观察的表现。
- 确认首发平台与地区、成员投入时间、预算上限和决策负责人。
- 初步识别内容来源、数据处理、技术、发布与人员方面的主要风险。
- 约定各阶段评审方式和调整原则。

首版学习目标可暂拟为：孩子经过一段时间使用后，在熟悉生活场景中能够听懂部分表达，并通过选择、动作或语言作出回应。具体语言范围、使用条件与观察周期由教研方案细化。

**交付物**

- 一页产品简报。
- 初步分龄与分能力方案。
- 团队职责表与投入安排。
- 预算框架和主要风险清单。
- 首版成功标准与里程碑评审方式。

**M1 通过标准**

团队对目标用户、核心价值和投入边界有一致理解，关键负责人明确，可以进入研究与样板准备。

**主要责任**

项目负责人组织；教研、设计、研发与运营共同参与。

### 4.2 第 3—5 周：验证需求，确定首版范围，完成 M2

**阶段目标**

用家庭的真实需求与行为证据，确定优先解决的问题和首版范围。

**主要工作**

- 建议访谈约 12—20 个目标家庭，覆盖不同年龄与英语基础。
- 观察部分家庭当前如何开展英语启蒙。
- 分别记录家长需求与儿童行为。
- 了解家庭在哪里中断、孩子需要多少帮助、家长已经为什么付过费。
- 同步请教教研人员，了解现有方法、产品及替代方案。
- 从本阶段开始建立后续试用家庭池。
- 用小规模内容、原型或技术任务试跑，初步测量团队使用 AI 后的实际产能。
- 初步估算内容制作、技术服务、用户招募和运营成本。

访谈应包含团队关系之外的家庭，并记录样本来源。人数是招募工作量建议，不代表统计代表性。

**交付物**

- 研究记录与需求结论。
- 家长和儿童的核心使用流程。
- 首版需求清单与暂缓事项。
- 试用家庭招募计划。
- 初步内容、技术与运营成本估算。
- AI 辅助制作的初步工时与返工记录。

**M2 通过标准**

找到需求相近的核心家庭，明确优先解决的问题，有家庭愿意安排时间持续试用，首版范围与资源基本匹配。

需求证据不足时，在此调整定位；范围过大时，在此缩减。

**主要责任**

产品与用户研究负责人牵头，教研和运营参与，项目负责人确定范围。

### 4.3 第 6—9 周：完成教学与体验样板，完成 M3

**阶段目标**

验证一个完整学习单元与完整使用流程，并确认团队能够重复制作合格内容。

**主要工作**

先完成以下教学链条：

接触语言 → 理解含义 → 作出回应 → 间隔复习 → 换情境使用。

样板同时包含：

- 孩子首次进入与活动引导。
- 一次完整学习活动。
- 错误处理与反馈。
- 完成反馈与再次使用。
- 复习安排。
- 家长查看结果与理解学习目的。

先围绕核心年龄段完成可体验版本，再制作低龄和高龄适配样例。首轮可邀请约 5—8 个家庭观察，确保三个年龄段均有参与；发现明显差异时补充样本。

确定教学结构、角色、视觉、声音和交互样板，再扩大制作。

若语音识别或 AI 对话属于核心能力，在此阶段验证其效果、延迟、失败处理与成本。

实际跑通一次内容生产流程，记录一个单元从初稿到审校完成的工时、修改次数和成本。

**交付物**

- 完整教学单元与三段体验样例。
- 教学目标及复习安排。
- 视觉、声音与交互规范。
- 内容生产和审校模板。
- 单元实际工时、返工与成本记录。
- 关键技术验证结果。

**M3 通过标准**

孩子能理解并完成核心活动，家长理解使用目的；团队能按可承受的成本重复制作合格内容，关键技术风险有处理方案。

**主要责任**

教研和设计负责样板质量，研发负责可运行性与技术验证，产品负责组织家庭观察。

### 4.4 第 10—17 周：建设最小可用产品，完成 M4

**阶段目标**

将已通过样板验证的体验建设为家庭可以持续试用的产品，并准备足够内容。

**产品建设重点**

- 进入学习并找到适合的路径。
- 完成核心学习活动与复习。
- 保存进度，退出后可以继续。
- 向家长呈现必要的使用与学习反馈。
- 提供问题反馈渠道。
- 补齐必要的账号、权限、数据管理与异常处理。
- 完成关键设备、网络和恢复场景测试。

**内容建设重点**

- 制作至少覆盖 4 周使用与复习的内容。
- 建立制作、审校、发布与修改流程。
- 共用成熟主题和结构，分别验证三段的引导方式与难度。
- 建立后续内容的持续生产排期。

**并行准备**

使用记录、监护人流程、素材授权与发布准备在此阶段落实。家庭招募、设备测试和内容审校持续推进。

在真实家庭资料采集前，明确数据用途、采集范围、保留与删除机制，并按目标市场和平台复核适用要求。

**交付物**

- 可安装或可访问的内测版本。
- 至少 4 周内容储备与后续生产计划。
- 内容更新工具和审核发布流程。
- 必要的使用记录、家长入口与反馈渠道。
- 测试记录和关键问题处理结果。
- 已准备好的试用家庭名单及进入安排。

**M4 通过标准**

目标家庭可以自行开始并完成多次学习，进度保存和恢复可靠；三个年龄段的核心路径可运行，内容足够支撑下一阶段连续观察。

4 周储备是内测起点。后续内容从这一阶段开始持续生产，以支撑试运营时承诺的服务。

**主要责任**

研发牵头产品交付；教研与内容团队并行生产；测试、设计和运营共同验收。

### 4.5 第 18—23 周：验证持续使用，完成 M5

**阶段目标**

观察产品能否融入家庭生活，并识别不同年龄与能力人群中的有效体验和主要问题。

**招募与时间安排**

建议约 30—50 个目标家庭，按年龄与已有能力分组记录。

招募与安装准备在第 18 周前完成。第 18—21 周安排至少 4 周连续观察，第 22—23 周集中修正与复测。

若分批进入，各批次按自己的实际观察窗口报告结果；新增家庭需要保留足够观察时间，必要时顺延验收。

**主要观察内容**

| 方面 | 需要回答的问题 |
| --- | --- |
| 孩子体验 | 是否理解活动、能否完成、需要多少帮助、重复使用后是否仍愿意参与 |
| 家庭使用 | 能否融入日常安排、何时中断、哪些家庭留下或退出、原因是什么 |
| 初步学习表现 | 间隔一段时间或更换图片、材料、情境后，是否仍能理解或回应 |
| 内容与服务成本 | 内容供给是否跟得上、需要多少提醒、答疑和问题处理 |

试用前确定活跃频次、家长介入程度、复习观察等口径，分别查看各年龄段和能力组结果。

小样本学习表现用于改进产品。完成率、使用时长和原题正确率不足以单独代表学习效果，对外表述应与证据相匹配。

**交付物**

- 各年龄与能力组的使用报告。
- 家长帮助记录与退出原因。
- 复习及换情境表现。
- 缺陷与修正清单。
- 内容产能、人工支持和技术服务成本。
- 是否进入付费试运营的建议。

**M5 通过标准**

核心人群达到事先约定的使用标准，主要流失原因明确，影响使用的关键问题得到修正，具备扩大试用的依据。

若发生核心教学或使用流程的大改动，需要追加观察并重新估算排期。

**主要责任**

产品与运营组织观察和访谈；教研解释学习表现；研发与设计修正问题；项目负责人作阶段决策。

### 4.6 第 24—28 周：小范围收费上线，完成 M6

**阶段目标**

验证真实购买与服务交付，建立可管理的小规模运行能力。

**主要工作**

- 建议逐步累计向约 100—200 个目标家庭开放，包含前期继续参与的家庭，按家庭去重计算。
- 确定价格、权益、服务周期和交付承诺。
- 完成购买、权益恢复、退款、客服和问题处理。
- 完成发布材料、运行监控、版本恢复与必要数据恢复准备。
- 使用有限渠道与可控规模推广。
- 记录购买和退款原因，以及每户实际服务成本。
- 确认内容能覆盖已售权益，或已有经过验证、能够持续兑现承诺的生产能力。

上述规模是开放与招募建议，不等于付费家庭目标。真实购买、招募补贴、免费试用和模拟支付应分别记录。

**交付物**

- 可稳定运行的小范围发布版本。
- 经验证的适龄与能力范围。
- 价格、权益与服务说明。
- 购买、退款和客服流程。
- 发布材料、监控与恢复方案。
- 首批真实购买及交付记录。
- 实际运行成本与有限推广方案。

**M6 通过标准**

购买、学习交付和问题处理能够正常运行，出现真实付费，团队能够持续更新内容。

计划目标是三个年龄段均通过验收。某一段尚未通过时，需要明确决定延后整体发布，或缩小首发适用范围，并同步调整宣传与权益。

**主要责任**

产品和运营负责权益与服务；研发负责交易、运行和恢复；教研与内容团队负责持续交付；项目负责人决定发布范围。

### 4.7 第 9—12 个月：持续经营验证，完成 M7

**阶段目标**

判断产品是否值得扩大投入，以及下一阶段应服务谁、提供什么内容与能力。

**主要工作**

- 持续更新内容并观察不同进入批次的家庭。
- 分析留存、购买、退款和适用的续费数据。
- 区分自然回访、运营提醒后的使用与持续人工支持。
- 分析获客、内容、AI/语音、云服务和人工服务成本。
- 根据结果调整体验、定价、内容节奏和渠道。
- 比较各年龄段与能力组的表现，决定后续资源重点。

续费判断要匹配收费周期。例如销售年费后，年度续费需要等相应周期到来才能观察。

**交付物**

- 分批次经营报告。
- 各年龄与能力组的表现。
- 内容供给、技术与服务成本报告。
- 主要问题与改进优先级。
- 下一阶段目标、资源与投入计划。

**M7 完成标准**

证据足以支持扩大投入、聚焦某类家庭、调整方案或收缩范围的决策。

M7 的完成是作出有依据的决策，不预设商业模式必然成立。

**主要责任**

项目负责人组织经营评审，产品、教研、研发与运营共同提供证据。

## 5. 并行工作与团队分工

负责人可以兼任，但每项责任都需要明确承担者。

| 工作线 | 主要责任 | 推进关系 |
| --- | --- | --- |
| 产品与用户研究 | 定位、需求取舍、体验、验收决策 | 前期集中研究，之后随家庭反馈持续迭代 |
| 教研与内容 | 学习目标、内容结构、审校、复习与分层 | 先完成样板，开发期间批量生产，上线后持续供给 |
| 设计与素材 | 交互、角色、视觉、声音与资产规范 | 先确认样板，再按规范扩量 |
| 研发与质量 | 产品实现、数据、设备适配、测试与运行 | 前期验证技术风险，样板通过后集中建设 |
| 用户运营与发布 | 招募、试用跟进、客服、收费和发布 | 第 3 周起招募，随内测逐步建立服务能力 |

安排人员时，需要同时保障内容生产与研发，避免全部资源长期集中在编码。样板通过后，教研与内容供给是与软件建设并行的交付责任。

## 6. 全员 AI 的工作方式

建议统一采用：

人确定目标与约束 → AI 辅助生成和修改 → 对应负责人审查 → 真实场景验证 → 正式交付。

| 工作 | AI 重点承担 | 人工验收重点 |
| --- | --- | --- |
| 用户研究 | 整理记录、归纳问题、辅助检索 | 核对原始证据与结论 |
| 教研内容 | 初稿、活动变体、文案和素材辅助 | 语言准确性、教学逻辑、难度与适龄性 |
| 设计制作 | 原型、图像和声音初稿、方案探索 | 一致性、可理解性、质量与授权 |
| 研发测试 | 代码、测试、调试与文档辅助 | 核心流程、异常处理、数据与实际设备表现 |
| 用户运营 | 反馈整理、客服回复初稿、报告辅助 | 真实问题处理、权益说明与服务承诺 |

AI 带来的效率，以首月和样板阶段的实测结果校准，重点记录：

- 一个合格内容单元的实际交付时间与成本。
- 一个稳定功能从开始到验收的时间。
- 审校、修改与返工次数。
- AI、语音和云服务的实际费用。
- 当前生产速度能否持续支持内容更新。

家庭招募、连续数周使用、间隔后的复习表现和真实续费需要保留观察时间。AI 节省的制作工时优先用于多轮修改和分龄验证。

## 7. 预算与资源管理

预算至少覆盖以下类别，具体金额待团队、平台与服务范围明确后测算。

| 预算类别 | 需要计入的内容 |
| --- | --- |
| 人员与外包 | 稳定投入的人力、必要外包与专业审校 |
| 教研与内容 | 教研、配音、图像、音效、制作及授权 |
| AI 与基础设施 | AI、语音、云服务、存储与内容分发 |
| 研究与质量 | 家庭招募、测试激励、设备和发布准备 |
| 运营与经营 | 客服、支付费用与小规模推广 |
| 机动预算 | 返工与其他不确定性 |

每个里程碑同时检查进度、证据和成本。新增范围时，明确对应的资源增加、其他事项删减或时间调整。

4 周机动时间与机动预算分别管理，不能默认相互替代。

## 8. 验收与数据口径

### 8.1 测试前约定，测试后按证据评审

每次里程碑评审固定检查：

1. 交付物是否完成。
2. 证据是否支持进入下一阶段。
3. 尚未解决的问题与影响。
4. 下一阶段资源与成本。
5. 继续、返工、调整范围、延长观察或暂停的决定。

具体使用频次、完成比例、帮助程度、稳定性与成本阈值，在相应试验开始前确定。本文的样本数量是起步工作量建议，不是行业基准。

### 8.2 样本与分组

- 以家庭为主要招募单位，家长与孩子不重复计为两个家庭样本。
- 区分招募数、开始使用数、完成观察数及实际付费数。
- 记录熟人样本与外部样本来源。
- 跨轮次重复参加的家庭标记为重复样本。
- 按年龄、英语基础及使用条件分别观察。
- 各批次保留实际观察时间与产品版本。
- 将家长帮助、运营提醒和人工服务纳入记录。
- 保留退出家庭与完整分母，避免只看留下来的家庭。

### 8.3 不同里程碑关注的证据

| 里程碑 | 重点证据 |
| --- | --- |
| M1 | 目标、约束、负责人和资源边界 |
| M2 | 家庭实际行为、需求及试用投入意愿 |
| M3 | 完整活动可理解、可完成，内容可重复生产 |
| M4 | 家庭可自行使用，关键流程与恢复可靠 |
| M5 | 连续使用、家长介入、退出原因与初步学习表现 |
| M6 | 真实交易、权益兑现、问题处理与运行成本 |
| M7 | 跨批次留存、适用续费、成本与内容供给能力 |

## 9. 排期调整原则

主要排期风险包括家庭招募不足、分龄差异超出预期、内容与配音返工、素材授权未落实、关键语音或 AI 能力不达预期、设备适配问题、发布整改，以及团队实际投入不足。

处理原则：

- 核心假设未成立时，先调整定位或体验。
- 某年龄或能力路径未通过时，明确继续验证或调整首发范围。
- 核心教学与流程发生明显改动时，补充必要观察。
- 新增平台、地区、能力或服务时，重新估算资源和时间。
- 不用新增功能替代当前阶段的验收。
- 重大方向与范围由项目负责人决定，已确认边界内的实施细节由对应负责人推进。
- 变更同步更新需求、决策记录、计划与成本估算。

## 10. 正式细化排期前的待定事项

| 待定事项 | 需要形成的决定 |
| --- | --- |
| 首版学习目标 | 优先验证的具体能力、语言范围与可观察变化 |

| 收费方式 | 价格、权益、周期、免费体验与服务承诺 |
| 验收口径 | 使用、学习观察、质量、成本和各年龄段的具体门槛 |
